# 设备同步与冲突处理

CLI 与网页端共用同一账号的数据，但会被识别为独立设备。退出登录后，CLI 的设备身份仍会保留。登录、查询和同步云端数据都不会接管其他设备。

## 每次修改必须以最新云端为准

1. 自动同步账号的最新云端数据。
2. 根据最新数据计算本次修改，并展示预览供你确认。
3. 确认后保存；如果期间有其他设备更新了数据，本次修改会被拒绝。
4. 保存成功后同步本地数据。

离线或无法同步最新数据时，修改会停止，不支持离线修改后补传。`--dry-run` 会同步最新数据并展示草稿：可视化交互终端可选择“确认执行 / 取消”，默认取消，确认后才保存；`--json`、`--text` 和非交互环境只预览，不保存、不接管。可视化草稿的确认不代表授权接管，仍遵守下文的设备和数据冲突规则。

预览期间云端发生变化时，会提示 `DATA_CONFLICT`。请重新运行命令，并核对更新后的预览。即使使用 `--takeover`，也不能跳过这一步。

## 设备冲突与选择

账号当前由其他设备更新时，会提示 `DEVICE_CONFLICT`，交互终端提供：

- **使用云端最新数据**：同步本地数据，放弃本次修改，不接管；需要修改时重新运行命令。
- **接管并执行本次修改**：重新同步、重新计算、再次确认后提交，设备归属改为 CLI。
- **取消**：不提交，不接管。

选择接管后，仍会先同步最新数据并请你重新确认，避免覆盖其他设备刚保存的修改。

CLI 接管后，网页再次上传会出现网页已有的设备冲突提示；网页接管后，CLI 再写入也会提示。读取云端、查询持仓和登录不会接管。

## 脚本调用

```bash
# --yes 仅确认记账，遇到其他设备仍失败（退出码 6）
jgb trade buy 110022 --amount 100 --yes --json

# 明确允许接管；仍先同步最新数据
jgb trade buy 110022 --amount 100 --takeover --yes --json

# 单独预览，不接管
jgb trade buy 110022 --amount 100 --dry-run --json
```

`--json`、`--text` 和非交互环境不等待用户选择。`--yes` 不是接管授权；`DATA_CONFLICT` 不能靠增加 `--takeover` 解决。

JSON 错误写入 stderr，退出码为非零；stdout 不输出提示装饰。

| 错误码 | 处理方式 |
| --- | --- |
| `DEVICE_CONFLICT`，退出码 6 | 确认设备切换意图后重新运行，可显式接管 |
| `DATA_CONFLICT`，退出码 6 | 重新运行，重新同步和核对 |
| `CLOUD_READ_FAILED` | 恢复网络后重新执行；本次未提交 |
| `MIGRATION_REQUIRED` | 写入功能暂不可用，请稍后重试或联系用户支持；无需自行配置 |
| `COMMIT_UNKNOWN` | 可能已提交，先核对云端，不盲目重试 |

如果云端已经成功而本地缓存保存失败，结果仍返回 `submitted: true` 并附带 `cacheWarning`。下次操作会重新拉取，请勿重复记账。
